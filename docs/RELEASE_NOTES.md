## v0.8.1 — готово к деплою (сессия 2026-09-05): стабильность урока + холодный старт #39

Цель: убрать «зависания» и ошибки на уроке, снизить влияние холодного старта serverless-контейнера.

### Урок больше не ходит в Supabase из браузера (BFF)
- **Раньше:** `clear-answers-button`, `auto-complete-lesson`, `complete-lesson-button`, `lesson-progress-tracker` вызывали Supabase напрямую из браузера (anon key публично, 3–4 лишних запроса, риск 403/QUIC на базе).
- **Теперь:** серверные API-роуты: `/api/lesson/status`, `/api/lesson/progress`, `/api/lesson/clear-answers` (RPC `clear_lesson_answers`, 1 транзакция). Клиент — через `src/lib/lesson-api.ts` (fetch + `AbortSignal.timeout(20s)`).
- `page.tsx` урока: пропсы компонентов переведены на данные из BFF.

### Медиа через прокси (фикс 403 на mp3)
- `src/app/api/storage/[...path]/route.ts`: добавлен `Authorization: Bearer <anon key>` в запрос к Supabase Storage — **был 403** на `lesson-files/uploads/*/…mp3`.
- `src/lib/image-proxy.ts`: добавлены `proxyFileUrl()` и `proxyHtmlUrls()`; `block-renderer.tsx` и `submissions-list.tsx` отдают файлы уроков через `/api/storage`.

### Service Worker больше не ломает загрузку (console: `sw.js` TypeError)
- `public/sw.js`: `respondWith(undefined)` заменён на таймаут 15с + реальный `new Response(...)`/503; кэш `nf-v2`. Ошибка `Failed to convert value to 'Response'` исчезает.

### Холодный старт (#39) — решение «бесплатно + не зависает»
- Новый `/api/health` (лёгкий, без БД).
- **Решение по тарифу (05.09.2026):** автопинг НЕ ставим. Пинг каждые 4 мин = контейнер почти всегда «включён» ≈ аренда always-on (деньги, этап C1/C2); пинг из GitHub жжёт бесплатные 2000 мин/мес Actions (нужны для деплоев) и всё равно не попадает в окно простоя. Итог: важное (зависания/403/sw/BFF) исправлено в коде этой сессии; холодный старт остаётся как «первый заход 20–30с раз в период простоя» — терпимо, 0 ₽. Ручной прогрев перед заходом учеников: workflow `Warm container (manual)`.
- Если позже понадобится настоящий аптайм — это этап C1/C2 (аренда), а не keep-warm.

- Локальный smoke: `/api/health` → 200; `/api/lesson/status` без auth → 401 (корректно).
- **Не сделано:** браузерный регресс-тест урока (нужен до деплоя), деплой.

## v0.8.0 (задеплоен 2026-09-04) — скорость по всем дашборд-страницам + чат на 1 запрос

### Чат на 1 запрос (#38 / Деплой 1)
- **Раньше:** чат открывался за 5–7 запросов (`/api/auth/me` + `/api/chat/teachers` + `/api/chat` + N подзапросов Supabase).
- **Теперь:** 1 вызов серверного `POST /api/chat/init` → RPC `get_chat_data` в одной транзакции (данные профиля, учителя, история, подписка). Fallback `legacyInit` на старой логике, если RPC недоступен — чат не ломается.
- Файлы: `src/app/api/chat/init/route.ts`, `src/app/(dashboard)/tools/chat/page.tsx`.

### Депликация `auth.getUser`/`profiles` на дашборде (Деплой 2)
- **Раньше:** каждая серверная страница + layout дёргали Supabase по 2–3 раза (`auth.getUser` ×3, `profiles` ×2), независимо дублируя друг друга.
- **Теперь:** общий `src/lib/auth-cache.ts` — `getServerClient()` и `getCurrentUser()` через `React.cache()`: **1 клиент и 1 `auth.getUser` + 1 `profiles` на HTTP-запрос**.
- Затронуты: layout дэшборда, курсы (список/курс/урок), настройки, учительская (учителя, проверка), инструмент чат. Страницы лоадатся быстрее (меньше сетевых запросов к Supabase).

### Не сделано: B7 (кэш публичных страниц) — отклонено технически
- Проверено: `export const revalidate` на публичных страницах **не включает ISR** — они остаются dynamic, т.к. `supabaseFetch` (server.ts) ходит обычным `fetch` без `next:{revalidate}`. Кэш контента учителя рискован («не показывать устаревшее»). Возврат только при росте нагрузки.

### Проверка
- `npx tsc --noEmit` — чисто. `npm run build` — успешно (все дашборд-страницы собираются).
- Браузерное регресс-тестирование до деплоя: `/`, `/login` (вход админа), `/courses`, курс, урок (5 типов блоков), `/tools/chat`, `/settings`, `/admin/teachers`, `/admin/submissions` — 0 ошибок.
- Деплой: `73e60ff` → ревизия `deploy-1788547720` (ACTIVE). `/api/chat/init` и `/api/stats` на проде отвечают 401 без авторизации (корректно).

## v0.7.2 — готово к деплою

### Оптимизация N+1 → Postgres RPC (главный выигрыш по скорости)
Страницы больше **не опрашивают БД по 6–12 раз подряд** — сервер получает всё одним вызовом функции на Postgres (`SECURITY DEFINER`). 5 RPC-функций + 14 индексов в `supabase/rpc-aggregation.sql`:
- **Урок** (`get_lesson_page`): 12 → **1** запрос. Уроки с тяжёлыми блоками (Порядок/Групповой порядок/Память) открываются мгновенно (проверено: 13 блоков за ~0.2с одним вызовом).
- **Курс** (`get_course_page`): 6 → **1**.
- **Главная** (`get_home_data`): 10 → **1**.
- **Список курсов** (`get_course_list`): 9 → **1+1** (RPC + 1 доп. для прогресса).
- **Чат** (`get_chat_data`): подготовлен, подключение в следующих итерациях.
- Итог: **37 → 5** запросов по четырём главным страницам.

### Производительность / надёжность
- **Ускорение уроков (issue #34):** сборка всех сохранённых ответов ученика **одним** серверным запросом в `page.tsx` вместо **9** клиентских запросов к `block_submissions`. Урок 4 («Порядок», «Групповой порядок», «Игра в пары») грузится мгновенно.
- **Чат — автопрокрутка (issue #31):** после исправления скроллит вниз только при открытии чата и отправке своего сообщения; при фоновом обновлении (каждые 5с) позицию чтения вверх больше не сбрасывает.
- **Закалка соединений к Supabase (issue #35):** `Connection: close` на всех серверных клиентах + `/api/auth/me` (BFF) для клиентских страниц. Устранены случайные зависания 20–70с (в dev и на медленных сетях).
- **Инструменты (чат/карточки/словарь)** переведены с браузерного `supabase.auth.getUser()` на серверный `/api/auth/me` — открываются за ~1с, без браузерных зависаний.

### Проверено
- `tsc --noEmit` чист, `npm run build` проходит.
- Логин ~0.4с, главная ~2с, инструменты ~0.6–0.9с; 20/20 запросов без столов.

## v0.7.0 (2026-09-03)

### Мобильная оптимизация загрузки (issue #28)

**Главный фикс — «картинки не грузятся»:**
- Прокси `/api/storage` научился обрабатывать **оба** типа ссылок Supabase Storage — обычные (`/object/public/...`) и **подписанные** (`/object/sign/...?token=...`). Раньше подписанные уходили напрямую на `supabase.co` и не доезжали до браузера (провайдер обрывал соединение). Теперь все картинки идут через прокси.

**Оптимизация публичных страниц:**
- Публичные страницы переведены на компонент `StorageImage` (next/image): responsive `srcset`, **ленивая загрузка**, защита от «прыжков» вёрстки (`fill`).
- Сжатие картинок на лету через Sharp в прокси: `?w=` (ширина), `?q=` (качество), `?fm=` (формат), авто-поворот по EXIF, отдача WebP/AVIF по Accept браузера.
- **Кэш** `Cache-Control: max-age=86400, immutable` — повторные загрузки мгновенные.
- Мигрированы: главная, `/catalog`, `/content/[id]`, `/reviews`, `/about`, `/teachers`, `/teachers/[id]`, карусель контента, слайдшоу, CTA.
- Тяжёлые клиентские библиотеки (редактор/ProseMirror, recharts-графики) подтверждены **вне публичного пути** — на лендинг не подгружаются.

**Новые загрузки:**
- `/api/upload-file` теперь возвращает **public URL** вместо подписанного (надёжнее для будущих картинок). Существующий контент учителя **не изменён** — старые картинки работают через прокси как раньше, но быстрее.

**Прочее:**
- `TwemojiGlobal` — пропуск уже обработанных поддеревьев (меньше нагрузки при перерисовке).
- В dev-режиме для удобной проверки вёрстки добавлена заглушка-плейсхолдер вместо реального файла (на прод не влияет — там только `NODE_ENV=production`).

### Исправлено
